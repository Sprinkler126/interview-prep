核心概念详解

概念说明
Dashboard仪表盘，由多个 Panel 组成的可视化页面。支持文件夹组织、权限控制、分享链接
Panel面板，Dashboard 的基本单元。每个 Panel 包含查询、可视化设置和告警规则
Data Source数据源，Grafana 支持多种后端数据存储（Prometheus、ES、MySQL 等）
Variable变量，实现仪表盘的动态过滤和复用。支持查询、自定义、间隔等类型
Row行，用于组织和分组 Panel，支持折叠
Annotation注释，在图表上标记事件（如部署时间点）

变量与模板

变量类型

# 查询变量（从数据源动态获取值）
# Name: instance
# Type: Query
# Query: label_values(up, instance)

# 自定义变量
# Name: environment
# Type: Custom
# Values: dev,test,prod

# 间隔变量
# Name: interval
# Type: Interval
# Values: 1m,5m,15m,1h,6h,1d

# 在查询中使用变量
rate(http_requests_total{instance="$instance"}[$interval])
  • 变量使 Dashboard 可以动态切换环境、实例、时间间隔
  • 支持级联变量（如选择环境后，实例列表自动过滤）
  • 变量值可通过 URL 参数传递，方便分享特定视图

告警规则（Grafana Alerting 8.x+）

Grafana 告警架构

Grafana Alerting 工作流
Alert Rule
定义告警条件
→
Evaluation
定期评估
→
Alert Instance
触发告警实例
→
Notification Policy
路由 + 分组
→
Contact Point
发送通知
  • Alert Rule：定义告警条件（PromQL / 日志查询）和评估间隔
  • Notification Policy：定义告警路由规则（按标签匹配）
  • Contact Point：定义通知渠道（Email / Slack / 钉钉）
  • Silence：静默规则，临时屏蔽告警
  • Mute Timing：静默时间段（如每天凌晨维护窗口）

Provisioning（Dashboard as Code）

Provisioning 配置

# grafana/provisioning/dashboards/dashboard.yml
apiVersion: 1
providers:
  - name: 'default'
    orgId: 1
    folder: 'Infrastructure'
    type: file
    disableDeletion: false
    updateIntervalSeconds: 30
    options:
      path: /var/lib/grafana/dashboards
      foldersFromFilesStructure: true

# grafana/provisioning/datasources/datasource.yml
apiVersion: 1
datasources:
  - name: Prometheus
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    isDefault: true
    editable: true
  • Dashboard JSON 文件存储在 Git 仓库中，实现版本控制
  • 修改 JSON 文件后 Grafana 自动加载更新
  • 数据源也可以通过 Provisioning 配置
  • 适合 GitOps 工作流，Dashboard 配置可追溯

第三部分：模拟面试

Grafana 的核心概念有哪些？Dashboard、Panel、Data Source 分别是什么？
参考：Dashboard 是仪表盘，由多个 Panel 组成的可视化页面。Panel 是面板，Dashboard 的基本单元，包含查询、可视化设置和告警规则。Data Source 是数据源，Grafana 支持多种后端存储（Prometheus、ES、MySQL、Loki 等）。Variable 是变量，实现仪表盘的动态过滤和复用。核心优势是一个 Dashboard 可以同时展示多个不同数据源的数据。
Grafana 8.x+ 的告警系统有什么改进？和 Prometheus Alertmanager 有什么区别？
参考：Grafana 8.x+ 引入了统一告警系统（Unified Alerting），不再依赖 Panel 的告警规则。改进：1）支持多数据源告警（不限于 Prometheus）；2）内置 Notification Policy 和 Contact Point 管理；3）支持 Mute Timing（静默时间段）；4）原生支持告警分组和路由。与 Alertmanager 的区别：Grafana 告警更适合多数据源场景，Alertmanager 专注于 Prometheus 告警处理。两者可以共存。
什么是 Grafana 的 Provisioning？有什么好处？
参考：Provisioning 是 Grafana 的"配置即代码"功能，允许通过 YAML/JSON 文件配置数据源和 Dashboard。好处：1）Dashboard 配置存储在 Git 仓库，实现版本控制；2）修改配置文件后自动加载，无需手动导入；3）适合 GitOps 工作流；4）环境一致性（开发、测试、生产使用相同 Dashboard）。配置路径：grafana/provisioning/datasources/ 和 grafana/provisioning/dashboards/。
Grafana 支持哪些数据源？如何选择？
参考：Grafana 支持 Prometheus（时序指标）、Elasticsearch（日志分析）、MySQL/PostgreSQL（业务数据）、InfluxDB（时序数据）、Loki（日志）、Jaeger/Zipkin（链路追踪）、CloudWatch（云监控）等。选择建议：指标监控用 Prometheus（最成熟），日志用 Loki（轻量级，Grafana 出品）或 ELK，链路追踪用 Jaeger/SkyWalking，业务数据用 MySQL。一个 Dashboard 可混合多个数据源。
Grafana 的变量（Variable）有什么作用？如何使用？
参考：变量使 Dashboard 可以动态切换参数，实现一个模板适用于多个环境/实例。类型：Query（从数据源动态查询，如获取所有实例 IP）、Custom（手动定义值列表，如 dev/test/prod）、Interval（时间间隔，如 1m/5m/15m）。使用方式：在查询中引用 $variable，如 rate(http_requests_total{instance="$instance"}[$interval])。支持级联变量，选择环境后实例列表自动过滤。
Grafana 的权限管理是怎样的？
参考：Grafana 的权限层级：Organization（顶层组织）→ Team（团队）→ 用户角色（Admin/Editor/Viewer）。Admin 可以管理所有资源，Editor 可以编辑 Dashboard，Viewer 只能查看。权限可以细化到文件夹和单个 Dashboard 级别。Team 可以共享 Dashboard 和文件夹权限。Enterprise 版本支持更细粒度的角色权限控制（RBAC）。
