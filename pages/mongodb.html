1.1 文档模型与 BSON 格式

文档模型 vs 关系模型
维度关系模型 (MySQL)文档模型 (MongoDB)
数据单元行 (Row)文档 (Document)
结构固定 Schema，列预先定义Schema-less，字段可动态增减
嵌套能力不支持，需 JOIN天然支持嵌套文档和数组
关系表达外键 + JOIN嵌入或引用（ObjectId）
扩展性加列需 ALTER TABLE直接写入新字段即可
事务原生 ACID4.0+ 多文档事务

BSON (Binary JSON) 格式

BSON 是 MongoDB 的底层存储格式，是 JSON 的二进制扩展。

BSON 文档示例
{
  _id: ObjectId("507f1f77bcf86cd799439011"),
  name: "张三",
  age: 28,
  address: {
    city: "北京",
    district: "海淀"
  },
  tags: ["Java", "MongoDB", "分布式"],
  createdAt: ISODate("2026-01-15T08:00:00Z")
}
  • 类型丰富：支持 Date、ObjectId、Decimal128、Binary 等 JSON 没有的类型
  • 字段名冗余：每条文档都存储字段名，适合 Schema 灵活但空间效率略低于关系型
  • 遍历友好：通过 length prefix 支持跳过不需要的字段，解析高效
  • 大小限制：单文档最大 16MB（BSON 格式）
  • _id 字段：每个文档必须有，自动创建索引，通常使用 ObjectId（12字节：时间戳+机器+进程+计数器）

1.2 CRUD 操作

Create / Insert

// 插入单条
db.users.insertOne({ name: "张三", age: 28 })

// 批量插入
db.users.insertMany([
  { name: "李四", age: 30 },
  { name: "王五", age: 25 }
])
  • 默认无序插入，任一失败不影响其他
  • 可设置 { ordered: true } 有序插入

Read / Find

// 条件查询
db.users.find({ age: { $gte: 25 } })

// 投影 + 排序 + 分页
db.users.find({ status: "A" })
  .projection({ name: 1, age: 1 })
  .sort({ age: -1 })
  .skip(10).limit(10)
  • 支持 $eq/$ne/$gt/$gte/$lt/$lte/$in/$nin
  • $regex 正则匹配、$elemMatch 数组元素匹配

Update

// 更新操作符
db.users.updateOne(
  { name: "张三" },
  {
    $set: { age: 29 },
    $push: { tags: "Spring" },
    $inc: { loginCount: 1 }
  }
)

// upsert: 不存在则插入
db.users.updateOne(
  { name: "赵六" },
  { $set: { age: 22 } },
  { upsert: true }
)

Delete

// 删除单条
db.users.deleteOne({ name: "张三" })

// 批量删除
db.users.deleteMany({ age: { $lt: 18 } })
  • $set 设置字段、$unset 移除字段
  • $inc 自增、$mul 乘法
  • $push/$pull 数组操作
  • $addToSet 去重添加

1.3 索引类型

MongoDB 索引类型总览
索引类型语法适用场景
单字段索引db.col.createIndex({ age: 1 })单字段查询，1 升序 / -1 降序
复合索引db.col.createIndex({ a: 1, b: -1 })多字段组合查询，遵循 ESR 原则（Equality → Sort → Range）
多键索引db.col.createIndex({ tags: 1 })自动为数组字段每个元素创建索引条目
文本索引db.col.createIndex({ content: "text" })全文搜索，支持中英文分词
地理空间索引db.col.createIndex({ loc: "2dsphere" })地理位置查询（$near、$within）
哈希索引db.col.createIndex({ _id: "hashed" })等值查询，分片集群哈希分片
TTL 索引db.col.createIndex({ ts: 1 }, { expireAfterSeconds: 3600 })自动过期删除文档（如 session）
唯一索引db.col.createIndex({ email: 1 }, { unique: true })字段值唯一约束

复合索引 ESR 原则

Equality
等值匹配字段放最前
→
Sort
排序字段放中间
→
Range
范围查询字段放最后

示例：find({ status: "A", age: { $gt: 20 } }).sort({ score: -1 })，最优索引为 { status: 1, score: -1, age: 1 }

explain() 执行计划分析

db.users.find({ age: { $gt: 25 } }).explain("executionStats")
关键指标说明
stage: "COLLSCAN"全集合扫描（未命中索引），性能差
stage: "IXSCAN"索引扫描，性能好
stage: "FETCH"回表查询，从索引定位到完整文档
totalDocsExamined扫描文档数，越少越好
totalKeysExamined扫描索引键数

1.4 聚合管道

聚合管道 (Aggregation Pipeline) 工作流
$match
过滤文档
→
$group
分组聚合
→
$project
字段投影
→
$sort
排序
→
$limit
限制条数
常用聚合阶段详解
阶段作用示例
$match过滤文档，类似 find 的查询条件{ $match: { status: "A" } }
$group分组聚合，支持 $sum/$avg/$max/$min/$push{ $group: { _id: "$dept", total: { $sum: "$salary" } } }
$project控制输出字段，可计算新字段{ $project: { name: 1, fullName: { $concat: ["$first"," ","$last"] } } }
$lookup关联查询（类似 LEFT JOIN）{ $lookup: { from: "orders", localField: "_id", foreignField: "userId", as: "orders" } }
$unwind展开数组字段，每个元素生成一条文档{ $unwind: "$tags" }
$sort排序{ $sort: { age: -1 } }
$limit / $skip分页{ $skip: 10 }, { $limit: 10 }
$addFields添加新字段（不删除原有字段）{ $addFields: { year: { $year: "$date" } } }
$facet多管道并行聚合同时计算分页 + 统计总数

聚合管道优化原则

  • $match 尽量前置：提前过滤减少后续阶段处理的数据量
  • $project 早用：减少传输字段，降低内存消耗
  • $match 能用索引：放在管道开头且匹配索引条件时可利用索引
  • $sort + $limit 合并：MongoDB 可优化为 top-N 排序
  • allowDiskUse：超过 100MB 内存限制时允许写磁盘（{ allowDiskUse: true }）

1.5 WiredTiger 存储引擎

WiredTiger 架构
客户端请求层
mongod 接收读写请求
⬇️
文档级别锁
非表锁，高并发
MVCC 快照
读写不阻塞
检查点
60s 一次快照
⬇️
缓存 (Cache)
默认 50% 系统内存
Journal (WAL)
预写日志
⬇️
磁盘存储 — B+Tree 索引 + 数据文件（Snappy/zlib 压缩）
数据文件压缩率 70%+ · 索引前缀压缩

WiredTiger 核心特性

  • B+Tree 索引：聚簇索引，数据按 _id 有序存储，叶子节点存完整文档
  • 文档级别并发控制：使用乐观并发控制协议，读写操作互不阻塞
  • 数据压缩：Snappy（默认）或 zlib 压缩，减少磁盘 IO 和存储空间
  • MVCC：每个操作看到的是某一时间点的快照，读写不互相阻塞
  • 检查点机制：默认 60 秒创建一致性快照，崩溃恢复从最近检查点 + journal 重放
  • 缓存管理：默认使用系统内存的 50%，脏数据达到阈值时触发淘汰写盘

1.6 事务支持

MongoDB 事务演进
版本事务能力
4.0 之前仅支持单文档原子操作（同一文档的多字段更新是原子的）
4.0副本集多文档 ACID 事务
4.2分片集群多文档 ACID 事务
4.4+可重试写入、隐式创建集合、事务内可修改多集合

多文档事务使用示例

const session = client.startSession();
session.startTransaction();
try {
  db.accounts.updateOne(
    { _id: "A" }, { $inc: { balance: -100 } }, { session }
  );
  db.accounts.updateOne(
    { _id: "B" }, { $inc: { balance: 100 } }, { session }
  );
  session.commitTransaction();
} catch (e) {
  session.abortTransaction();
} finally {
  session.endSession();
}
事务有 60 秒超时限制（可调），过大的事务会影响性能。MongoDB 推荐优先使用嵌入文档设计减少对多文档事务的依赖。

🎯第二部分：场景化讲解

2.1 嵌入 vs 引用设计

📦 嵌入 (Embedding)

{
  userId: "u001",
  name: "张三",
  orders: [
    { orderId: "o1", item: "手机", price: 5999 },
    { orderId: "o2", item: "耳机", price: 299 }
  ]
}
  • 优点：一次查询获取全部数据，原子性更新
  • 缺点：文档膨胀（16MB 限制），更新子文档会导致整个文档重写
  • 适用：1:1 或 1:少量 关系，数据一起读取、一起更新

🔗 引用 (Referencing)

// users 集合
{ _id: "u001", name: "张三" }

// orders 集合
{ _id: "o1", userId: "u001", item: "手机" }
{ _id: "o2", userId: "u001", item: "耳机" }
  • 优点：文档小，子文档独立更新，避免重复
  • 缺点：需额外查询或 $lookup 关联
  • 适用：1:多、多:多 关系，子文档独立生命周期

设计决策原则

场景推荐方式原因
用户 + 地址（少量）嵌入总是随用户一起查询
博客 + 评论（海量）引用评论可能无限增长
商品 + SKU嵌入SKU 数量有限且固定
用户 + 订单引用订单持续增长，独立查询
文章 + 标签混合标签嵌入文章，也维护独立标签集合

2.2 副本集架构

MongoDB 副本集 (Replica Set)
Primary
接受所有读写
oplog 写入
→ oplog →
Secondary 1
同步 oplog
Secondary 2
同步 oplog

Primary 选举机制

  • 心跳检测：节点之间每 2 秒发送心跳，10 秒无响应标记为不可达
  • 触发选举：Primary 不可达超过 electionTimeout（默认 10s），Secondary 发起选举
  • 投票规则：每个节点一票，获得多数派（N/2 + 1）票数的节点成为新 Primary
  • Priority：优先级高的节点优先当选（0 表示永不成为 Primary）
  • Oplog：操作日志是 Capped Collection，Secondary 持续拉取 Primary 的 oplog 进行重放

读写分离

// 从 Secondary 读取（最终一致性）
db.users.find().readPref("secondary")

// readPreference 选项
// primary（默认）: 只从 Primary 读
// primaryPreferred: 优先 Primary，不可用时从 Secondary 读
// secondary: 只从 Secondary 读
// secondaryPreferred: 优先 Secondary
// nearest: 延迟最低的节点
默认写入 WriteConcern: { w: 1 }（Primary 确认即可），需要更高持久性可设置 { w: "majority" }（多数节点确认）。

Shard Key 选择

策略特点示例
范围分片 (Range)支持范围查询，但可能产生热点{ _id: 1 }，时间戳递增导致写集中到一个 shard
哈希分片 (Hashed)数据均匀分布，但范围查询需广播{ userId: "hashed" }
复合分片兼顾查询和分布{ region: 1, userId: "hashed" }
Shard Key 一旦选定不可更改！选择原则：高基数（cardinality）、低频变化、查询常用。

Chunk 迁移与 Balancer

  • Chunk：数据按 Shard Key 范围划分为 chunk（默认 128MB）
  • Balancer：后台进程监控各 shard 的 chunk 数量差异，自动迁移 chunk 实现均衡
  • 迁移过程：源 shard 复制 chunk → 目标 shard 写入 → Config Server 更新映射 → 源 shard 删除
  • 分裂：chunk 大小超过阈值时自动分裂为更小的 chunk

🎤第三部分：模拟面试

MongoDB 的文档模型和关系模型有什么区别？什么场景下选择 MongoDB？
参考：文档模型 Schema 灵活，支持嵌套和数组，开发迭代快。关系模型强 Schema、强一致性。
选 MongoDB 的场景：① Schema 频繁变化；② 数据层次深、嵌套多；③ 高写入吞吐；④ 需水平扩展。
追问：如果业务需要复杂 JOIN 和强事务，还是选关系型数据库更合适。
MongoDB 的 WiredTiger 存储引擎有什么特点？
参考：① B+Tree 索引；② 文档级别锁（乐观并发控制）；③ MVCC 快照隔离；④ Snappy 压缩（数据压缩 70%+）；⑤ 60s 检查点 + Journal WAL；⑥ 缓存默认占系统内存 50%。
MongoDB 副本集的选举机制是怎样的？
参考：节点间每 2s 心跳，Primary 10s 无响应触发选举。每个节点一票，获得多数派票数（N/2+1）的节点成为新 Primary。Priority 高优先，Priority=0 永不参选。至少 3 个节点（1主2从）才能自动故障转移。
如何选择 Shard Key？范围分片和哈希分片有什么区别？
参考：Shard Key 选择原则——高基数、低频变化、查询常用。范围分片支持范围查询但可能热点（如递增时间戳），哈希分片数据均匀但范围查询需广播。Shard Key 不可更改，必须在分片前规划好。
追问：复合分片（如 region + hashed userId）可兼顾两者优势。
MongoDB 聚合管道的优化原则有哪些？
参考：① $match 尽量前置（可利用索引）；② $project 早用（减少字段传输）；③ $sort+$limit 合并优化；④ allowDiskUse 处理大数据集；⑤ 避免 $lookup 嵌套（性能差）。
追问：$match 放在管道开头可以利用集合索引，放到后面则只能在内存中过滤。
MongoDB 的多文档事务是怎么实现的？有什么性能影响？
参考：4.0 支持副本集多文档事务，4.2 支持分片集群。基于 WiredTiger 的 MVCC 实现快照隔离。性能影响：① 事务有 60s 超时；② 写冲突需重试；③ 大事务占用缓存。建议优先使用嵌入文档设计减少事务需求。
MongoDB 嵌入和引用设计怎么选？
参考：嵌入适合 1:少量、数据一起读写的场景（如用户+地址）。引用适合 1:多、数据独立生命周期的场景（如用户+订单）。混合方式也常见。
追问：嵌入文档有 16MB 限制，子文档数量大时必须用引用。引用需 $lookup 关联，性能不如嵌入直读。
MongoDB 如何保证高可用？
参考：① 副本集（Primary-Secondary，自动故障转移）；② 分片集群（每个 shard 是副本集 + Config Server 也是副本集）；③ WriteConcern: majority 确保多数节点写入成功；④ ReadPreference 控制读节点选择。
追问：生产环境推荐 3 节点副本集 + majority 写入确认。
