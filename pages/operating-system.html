🔬第一部分：技术原理

1.1 进程 / 线程 / 协程

进程 vs 线程 vs 协程

特性进程线程协程
定义资源分配的基本单位CPU 调度的基本单位用户态的轻量级线程
资源独立地址空间、文件描述符等共享进程资源，有独立栈和寄存器共享线程资源，有独立栈
切换开销大（切换地址空间、TLB 刷新）中等（切换内核栈、寄存器）极小（用户态切换，无内核参与）
通信IPC（管道/消息队列/共享内存等）共享内存（需同步机制）共享内存（无锁/少锁）
创建销毁重量级中等轻量级
调度OS 内核调度OS 内核调度用户态调度（不被 OS 感知）
典型实现fork()、multiprocessingpthread、java.lang.ThreadGo goroutine、Lua coroutine

进程状态

创建（New）
→
就绪（Ready）
→
运行（Running）
→
终止（Terminated）
  • 就绪 → 运行：被调度器选中，获得 CPU
  • 运行 → 就绪：时间片用完，被抢占
  • 运行 → 阻塞：等待 IO 或事件（如 I/O 请求、sleep、等待锁）
  • 阻塞 → 就绪：等待的事件发生（如 I/O 完成）
  • 挂起状态：内存不足时，将阻塞进程换出到磁盘（挂起阻塞/挂起就绪）

1.2 进程调度算法

调度算法对比

算法全称特点问题
FCFS先来先服务简单公平，非抢占护航效应（短作业等长作业）
SJF最短作业优先平均等待时间最短长作业饥饿，需预知执行时间
SRTF最短剩余时间优先SJF 的抢占版本长作业饥饿
RR时间片轮转公平，响应快时间片太大退化为 FCFS，太小切换开销大
优先级优先级调度重要任务优先执行低优先级饥饿
MLFQ多级反馈队列综合优先级和时间片，动态调整实现复杂
多级反馈队列（MLFQ）：多个队列，优先级从高到低，时间片从小到大。新进程进入最高优先级队列，时间片内未完成则降到下一级。是 Unix/Linux 调度器的基础思想。

1.3 进程间通信（IPC）

IPC 方式对比

方式原理优点缺点
管道（Pipe）内核缓冲区，单向字节流简单单向、只能父子进程、缓冲区有限
命名管道（FIFO）文件系统中的管道无亲缘关系进程可用单向、慢
消息队列内核中的消息链表格式化消息、异步复制开销、大小限制
共享内存多个进程映射同一块物理内存最快（零拷贝）需要同步机制（信号量/互斥锁）
信号量（Semaphore）计数器，用于同步和互斥高效同步编程复杂
Socket网络通信接口跨机器通信开销较大
Java 中的 IPC：① Socket/RMI（跨 JVM）；② 共享内存（MappedByteBuffer）；③ 管道（PipedInputStream/OutputStream）；④ 消息队列（第三方如 RocketMQ）。

1.4 线程同步

同步机制对比

机制特点适用场景
互斥锁（Mutex）独占访问，阻塞等待保护临界区
读写锁（RWLock）读共享、写独占读多写少
条件变量（Condition）配合互斥锁，等待/通知生产者-消费者
信号量（Semaphore）计数器，允许多个线程同时访问资源池、限流
自旋锁（Spinlock）忙等待，不释放 CPU临界区极短、多核
原子操作（CAS）硬件级原子指令计数器、无锁数据结构
自旋锁 vs 互斥锁：自旋锁在用户态忙等，适合临界区很短（微秒级）的场景，避免线程切换开销；互斥锁会阻塞线程，适合临界区较长的场景。Java 中的 synchronized 在竞争不激烈时使用自旋锁，竞争激烈时升级为重量级锁。

1.5 死锁

死锁四个必要条件

条件含义
互斥资源一次只能被一个线程占用
占有并等待持有资源的线程还在等待其他资源
不可剥夺已获得的资源不能被强行夺走
循环等待存在线程的循环等待链

死锁处理策略

预防（破坏条件）

  • 破坏占有等待：一次性申请所有资源
  • 破坏不可剥夺：申请不到则释放已有资源
  • 破坏循环等待：按固定顺序申请资源

避免（银行家算法）

  • 每次分配前检查是否安全状态
  • 安全状态：存在一个安全序列使所有进程都能完成
  • 实际应用较少（需预知最大需求）

检测与恢复

  • 检测：构建资源分配图，检测环路
  • 恢复：终止进程 / 资源回滚
  • 数据库常用：等待图检测 + 超时回滚

忽略（鸵鸟策略）

  • 假装死锁不存在
  • 死锁概率极低时可接受
  • Unix/Windows 采用此策略

1.6 虚拟内存

虚拟内存机制

CPU 生成虚拟地址
→
查 TLB（快表）
→
未命中 → 查页表
→
得到物理地址 → 访问内存
  • 页表：虚拟页号 → 物理页号的映射表，每个进程独立
  • TLB（Translation Lookaside Buffer）：页表的高速缓存，减少页表查询开销
  • 缺页中断：访问的页不在内存中，触发中断，从磁盘调入内存
  • 多级页表：减少页表占用的连续内存（如 4 级页表：PGD → PUD → PMD → PTE）

页面置换算法

算法策略特点
OPT替换未来最长时间不会被访问的页理论最优，无法实现（需要预知未来）
FIFO替换最早进入内存的页简单，可能抖动（Belady 异常）
LRU替换最近最久未使用的页接近 OPT，实现开销大（需维护访问时间）
Clock环形链表 + 访问位，指针扫描LRU 的近似，实现简单
LFU替换访问频率最低的页可能被历史数据影响
Belady 异常：FIFO 算法在增加物理页框数时，缺页率反而可能上升。LRU 和 OPT 不会出现此异常。

内存管理方式

方式原理优点缺点
分页将内存和进程分为固定大小的页无外部碎片有内部碎片
分段按逻辑单元分为大小不等的段符合程序逻辑外部碎片
段页式先分段，段内再分页兼具两者优点地址转换复杂

2.1 IO 模型

五种 IO 模型

模型特点阶段
阻塞 IOread 时线程阻塞直到数据就绪并复制完成全程阻塞
非阻塞 IOread 立即返回（EAGAIN），需轮询数据准备阶段不阻塞，复制阶段阻塞
IO 多路复用select/poll/epoll 监听多个 fd等待就绪阶段阻塞，复制阶段阻塞

异步 IOaio_read 全程不阻塞，完成后回调全程不阻塞
前四种都是同步 IO（数据复制阶段阻塞），只有 AIO 是真正的异步 IO。Java NIO 对应 IO 多路复用模型。

特性selectpollepoll

2.2 epoll 原理

epoll 内部结构

epoll 核心数据结构
红黑树（RB-Tree）
存储所有被监听的 fd，O(log n) 增删改
就绪链表（Ready List）
IO 就绪的 fd 通过回调加入此链表，O(1) 获取就绪事件
  • epoll_create：创建 epoll 实例，初始化红黑树和就绪链表
  • epoll_ctl：向红黑树增删改 fd，注册回调函数
  • epoll_wait：检查就绪链表，有就绪事件则返回，否则阻塞等待

LT（水平触发）vs ET（边缘触发）

LT（Level Triggered）

  • 只要 fd 处于就绪状态，每次 epoll_wait 都会通知
  • 编程简单，不易丢数据
  • 可能有重复通知的开销
  • select/poll 默认模式

ET（Edge Triggered）

  • 只在 fd 状态变化时通知一次
  • 性能更高，减少 epoll_wait 调用
  • 必须一次性读完数据（循环读直到 EAGAIN）
  • 必须配合非阻塞 IO 使用

2.3 用户态与内核态

用户态 vs 内核态

  • 用户态：进程只能访问受限的内存和指令，不能直接操作硬件
  • 内核态：可以访问所有内存和指令，执行特权操作
  • 系统调用：用户态 → 内核态的唯一入口（如 read、write、fork、mmap）
  • 中断：硬件中断（如 IO 完成）和软件中断（如系统调用 int 0x80）触发态切换
  • 切换开销：保存/恢复寄存器、切换栈、刷新 TLB（部分）
用户进程调用系统调用
→
陷入内核（trap）
→
内核执行系统调用
→
返回用户态

2.4 文件系统

inode 与文件结构

  • inode：存储文件的元数据（大小、权限、时间戳、数据块指针），不包含文件名
  • 目录：特殊的文件，内容是 文件名 → inode号 的映射表
  • 数据块：存储文件实际内容，通过 inode 中的指针找到

硬链接 vs 软链接（符号链接）

硬链接

  • 多个文件名指向同一个 inode
  • 不能跨文件系统
  • 不能链接目录
  • 删除原文件不影响（引用计数 -1）
  • ln source hardlink

软链接

  • 独立的 inode，内容是目标路径
  • 可以跨文件系统
  • 可以链接目录
  • 原文件删除后失效（悬空链接）
  • ln -s source symlink

🎤第三部分：模拟面试

进程和线程的区别是什么？什么时候用多进程，什么时候用多线程？
参考：进程是资源分配的基本单位，有独立地址空间；线程是 CPU 调度的基本单位，共享进程资源。线程创建/切换开销小，但一个线程崩溃可能影响整个进程。
多进程适用：需要高稳定性（如 Chrome 每个标签页一个进程）、需要隔离的场景。多线程适用：需要共享数据、频繁通信、计算密集型任务。
什么是死锁？如何预防死锁？
参考：死锁是两个或多个进程互相等待对方持有的资源，导致都无法继续执行。四个必要条件：互斥、占有并等待、不可剥夺、循环等待。
预防：① 破坏占有等待：一次性申请所有资源；② 破坏不可剥夺：申请不到则释放已有资源；③ 破坏循环等待：按固定顺序申请资源。实际中最常用的是按顺序加锁。
select、poll、epoll 有什么区别？为什么 epoll 性能更好？
参考：select 用位图存储 fd，最大 1024 个，每次调用都要全量拷贝 fd 集合，返回后需线性遍历。poll 用数组，无数量限制，但仍需全量拷贝和线性遍历。epoll 用红黑树存储 fd（mmap 共享内存避免拷贝），用就绪链表存储就绪事件，回调机制直接将就绪 fd 加入链表，无需遍历所有 fd。
追问：epoll 适合大量连接但活跃连接少的场景（C10K）。如果所有连接都活跃，epoll 的优势不明显。
虚拟内存是什么？缺页中断的过程？
参考：虚拟内存让每个进程拥有独立的虚拟地址空间，通过页表映射到物理内存。进程不需要知道物理内存的实际布局。
缺页中断：CPU 访问虚拟地址 → 查页表发现页不在内存（present 位为 0）→ 触发缺页中断 → 内核检查地址是否合法 → 选择牺牲页（页面置换算法）→ 从磁盘调入目标页 → 更新页表 → 重新执行触发缺页的指令。
五种 IO 模型的区别？什么是 IO 多路复用？
参考：阻塞 IO 全程阻塞；非阻塞 IO 轮询检查数据是否就绪；IO 多路复用用 select/poll/epoll 同时监听多个 fd；信号驱动 IO 用信号通知；异步 IO 全程不阻塞（内核完成数据复制后通知）。
IO 多路复用：一个线程同时监听多个 socket，当任一 socket 就绪时返回。是实现高并发网络服务器的核心技术。Java NIO 的 Selector 就是 IO 多路复用的封装。
硬链接和软链接的区别？
参考：硬链接：多个文件名指向同一个 inode，不能跨文件系统，不能链接目录，删除原文件不影响。软链接：独立的 inode，内容是目标文件路径，可以跨文件系统和链接目录，原文件删除后失效。
追问：为什么硬链接不能跨文件系统？因为 inode 号只在同一个文件系统内唯一。
用户态和内核态的区别？系统调用的过程？
参考：用户态进程只能访问受限资源，内核态可以访问所有资源。系统调用是从用户态切换到内核态的唯一入口。过程：用户进程发起系统调用 → 触发软中断（trap）→ CPU 切换到内核态 → 保存用户态上下文 → 执行内核代码 → 恢复上下文 → 返回用户态。
追问：态切换的开销包括什么？保存/恢复寄存器、切换栈指针、刷新 TLB（部分场景）。约几百纳秒量级。
自旋锁和互斥锁的区别？什么时候用自旋锁？
参考：互斥锁：获取不到锁时线程阻塞（睡眠），让出 CPU，适合临界区较长的场景。自旋锁：获取不到锁时线程忙等（循环检查），不让出 CPU，适合临界区极短（微秒级）的场景。
选择依据：① 临界区短且竞争不激烈 → 自旋锁（避免线程切换开销）；② 临界区长或竞争激烈 → 互斥锁（避免 CPU 空转）。多核 CPU 上自旋锁更有优势。
什么是协程？和线程有什么区别？Go 的 goroutine 是怎么实现的？
参考：协程是用户态的轻量级线程，由用户态调度器调度，不经过内核，切换开销极小（只保存/恢复少量寄存器）。
Go goroutine：初始栈仅 2KB（可动态增长），由 Go runtime 的 M:N 调度器管理（M 个 goroutine 映射到 N 个 OS 线程）。GMP 模型：G（goroutine）、M（OS 线程）、P（逻辑处理器，维护本地队列）。
