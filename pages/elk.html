Filebeat vs Logstash

Filebeat

  • Go 语言编写，轻量级
  • 内存占用 ~10MB
  • 只负责采集和发送，不做复杂处理
  • 支持背压敏感，不会丢失数据
  • 适合部署在每台服务器上
  • 支持多种输入：log、container、redis、kafka

Logstash

  • JRuby 编写，重量级
  • 内存占用 ~200MB+
  • 强大的数据处理能力（Filter）
  • 支持 Grok、Mutate、GeoIP 等插件
  • 适合集中式数据处理
  • 支持多种输入/输出

Logstash 管道

Input → Filter → Output

# logstash.conf
input {
  beats {
    port => 5044
  }
  # 也可以从 Kafka 消费
  kafka {
    bootstrap_servers => "kafka:9092"
    topics => ["app-logs"]
    group_id => "logstash-group"
  }
}

filter {
  # Grok 解析非结构化日志
  grok {
    match => {
      "message" => '%{TIMESTAMP_ISO8601:timestamp} \[%{LOGLEVEL:level}\] \[%{DATA:thread}\] %{GREEDYDATA:msg}'
    }
  }

  # 日期解析
  date {
    match => ["timestamp", "yyyy-MM-dd HH:mm:ss.SSS"]
    target => "@timestamp"
  }

  # Mutate 字段处理
  mutate {
    remove_field => ["timestamp", "message"]
    rename => { "msg" => "log_message" }
    convert => { "response_time" => "integer" }
  }

  # GeoIP 地理位置解析
  geoip {
    source => "client_ip"
    target => "geo"
  }
}

output {
  elasticsearch {
    hosts => ["es:9200"]
    index => "app-logs-%{+YYYY.MM.dd}"
    # 或使用 ILM
    # index => "app-logs"
  }
}

Grok / Mutate / GeoIP

Grok 解析

# Grok 语法：%{PATTERN:field_name}
# 常用 Pattern：
# %{TIMESTAMP_ISO8601:timestamp}  - 时间戳
# %{LOGLEVEL:level}               - 日志级别
# %{IP:client_ip}                 - IP 地址
# %{INT:status_code}              - 整数
# %{GREEDYDATA:message}           - 任意文本

# 示例：解析 Nginx access log
grok {
  match => {
    "message" => '%{IPORHOST:client_ip} - %{DATA:user} \[%{HTTPDATE:timestamp}\] "%{WORD:method} %{URIPATHPARAM:request} HTTP/%{NUMBER:http_version}" %{NUMBER:status_code} %{NUMBER:bytes}'
  }
}

常用 Filter 插件

插件作用示例
Grok正则解析非结构化日志解析 Nginx / 应用日志
Mutate字段重命名、删除、类型转换rename => {"msg" => "message"}
GeoIPIP 地址解析为地理位置geoip { source => "client_ip" }
Date日期解析date { match => ["timestamp", "ISO8601"] }
JsonJSON 解析json { source => "message" }
Dissect简单分隔符解析（比 Grok 快）dissect { mapping => {"message" => "%{ts} %{level} %{msg}"} }

{
  "policy": {
    "phases": {
      "hot": {
        "actions": {
          "rollover": {
            "max_size": "50gb",
            "max_age": "1d"
          }
        }
      },
      "warm": {
        "min_age": "7d",

日志规范

结构化日志最佳实践

# 推荐：JSON 结构化日志
{
  "timestamp": "2026-06-10T10:30:00.123Z",
  "level": "ERROR",
  "service": "user-service",
  "traceId": "abc123",
  "spanId": "def456",
  "thread": "http-nio-8080-exec-1",
  "logger": "com.example.UserService",
  "message": "Failed to create user",
  "exception": "java.lang.NullPointerException",
  "stackTrace": "...",
  "userId": "12345",
  "requestPath": "/api/users"
}
  • 结构化：使用 JSON 格式，便于 ES 索引和查询
  • TraceId：注入链路追踪 ID，便于关联日志和链路
  • 日志级别：ERROR / WARN / INFO / DEBUG / TRACE，生产环境 INFO
  • 敏感信息：不打印密码、Token 等敏感数据
  • 日志切割：按天/按大小切割，避免单文件过大

性能优化与安全

性能优化

  • 索引策略：按日期创建索引（如 app-logs-2026.06.10），使用 ILM 管理生命周期
  • 分片数量：单个分片建议 10-50GB，过多分片影响性能
  • 副本数量：写入密集时可临时设为 0，查询需要时再增加
  • JVM 调优：堆内存设置为物理内存的 50%（不超过 32GB），留内存给 OS 文件缓存
  • 批量写入：使用 Bulk API 批量索引，减少请求次数
  • Force Merge：对不再写入的索引执行 force merge，减少段数量

安全配置

  • X-Pack Security：ES 内置安全插件，支持认证和授权
  • TLS/SSL：节点间通信加密、客户端连接加密
  • RBAC：基于角色的访问控制，不同用户不同权限
  • API Key：程序化访问使用 API Key 而非用户名密码
  • 网络隔离：ES 集群不应暴露到公网

第三部分：模拟面试

ELK Stack 的架构是怎样的？各组件有什么作用？
参考：ELK 由三部分组成：Elasticsearch（分布式搜索引擎，负责日志的索引、存储和检索，基于倒排索引实现近实时搜索）、Logstash（数据处理管道，负责日志的过滤、转换和转发）、Kibana（可视化界面，提供 Discover（日志搜索）、Visualize（图表）、Dashboard（大屏）功能）。生产环境通常加入 Filebeat（轻量采集）和 Kafka（缓冲队列）。
Filebeat 和 Logstash 有什么区别？什么时候用哪个？
参考：Filebeat 是 Go 语言编写的轻量级采集器，内存占用约 10MB，只负责采集和发送，适合部署在每台应用服务器上。Logstash 是 JRuby 编写的重量级处理器，内存占用 200MB+，支持 Grok、Mutate 等强大的数据处理功能。生产方案：Filebeat 部署在每台服务器采集日志，发送到 Kafka 缓冲，Logstash 从 Kafka 消费并集中处理，然后写入 ES。
什么是 Grok？如何使用它解析日志？
参考：Grok 是 Logstash 的正则解析插件，用于将非结构化日志转换为结构化字段。语法：%{PATTERN:field_name}。常用 Pattern：TIMESTAMP_ISO8601（时间戳）、LOGLEVEL（日志级别）、IP（IP 地址）、INT（整数）、GREEDYDATA（任意文本）。示例：%{TIMESTAMP_ISO8601:timestamp} [%{LOGLEVEL:level}] %{GREEDYDATA:message}。对于简单分隔符日志，推荐使用 Dissect（性能更好）。
参考：ILM（Index Lifecycle Management）是 ES 的索引生命周期管理功能。它将索引分为四个阶段：Hot（写入+查询，SSD 存储）、Warm（只读+查询，HDD 存储）、Cold（低频查询，压缩存储）、Delete（过期删除）。通过 Rollover 策略自动创建新索引（按大小或时间），旧索引自动降级或删除。好处：避免单个索引过大、自动管理存储成本、保留合理的数据周期。
参考：最初是 ELK（Elasticsearch + Logstash + Kibana），Logstash 直接采集日志。后来 Filebeat 替代 Logstash 做采集（更轻量），形成 Filebeat + Logstash + ES + Kibana。EFK 是 Kubernetes 生态常用架构，用 Fluentd 替代 Logstash（Fluentd 是 CNCF 项目，与 K8s 集成更好）。生产级架构：Filebeat + Kafka + Logstash + ES + Kibana，加入 Kafka 做缓冲队列。
参考：分片（Shard）是 ES 的基本存储单元，数据被分散到多个分片上实现水平扩展。副本（Replica）是分片的复制，提供高可用和查询性能。设置建议：单个分片 10-50GB，日志场景按日期创建索引，每个索引 1-3 个主分片。副本数通常为 1（写入密集时可临时设为 0）。分片数在创建索引后不可修改（需要 Reindex），副本数可以动态调整。
参考：1）X-Pack Security：ES 内置安全插件，支持用户名密码认证和 RBAC 权限控制；2）TLS/SSL：节点间通信和客户端连接加密；3）API Key：程序化访问使用 API Key；4）网络隔离：ES 集群不应暴露到公网，使用防火墙限制访问；5）日志脱敏：不打印密码、Token 等敏感信息；6）审计日志：记录所有访问操作。
