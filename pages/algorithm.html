1.1 时间与空间复杂度

大 O 表示法

大 O 表示法描述算法执行时间随输入规模 n 增长的上界，忽略常数项和低阶项。

复杂度名称示例n=10^6 量级
O(1)常数哈希表查找、数组按下标访问1
O(log n)对数二分查找、平衡BST操作20
O(n)线性遍历数组、链表查找10^6
O(n log n)线性对数快速排序、归并排序、堆排序2×10^7
O(n^2)平方冒泡排序、选择排序、插入排序10^12

O(n!)阶乘全排列暴力枚举不可计算

主定理（Master Theorem）

用于求解递推关系 T(n) = aT(n/b) + O(n^d)，其中 a ≥ 1, b > 1, d ≥ 0：

条件结果示例
d < log_b(a)T(n) = O(n^(log_b(a)))Strassen 矩阵乘法：T(n)=7T(n/2)+O(n^2) → O(n^2.81)
d = log_b(a)T(n) = O(n^d log n)归并排序：T(n)=2T(n/2)+O(n) → O(n log n)
d > log_b(a)T(n) = O(n^d)二分查找：T(n)=T(n/2)+O(1) → O(log n)（特殊情况）
常见复杂度排序：O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)

快速排序（Quick Sort）

→

// 经典 Lomuto 分区
int partition(int[] arr, int lo, int hi) {
    int pivot = arr[hi], i = lo;
    for (int j = lo; j < hi; j++) {
        if (arr[j] <= pivot) { swap(arr, i, j); i++; }
    }
    swap(arr, i, hi);
    return i;
}

// 随机化快排：随机选 pivot 与 arr[hi] 交换，避免最坏 O(n^2)
// 三路快排（Dutch National Flag）：处理大量重复元素
// [lo...lt-1] < pivot | [lt...gt] == pivot | [gt+1...hi] > pivot
  • 优化：随机化选 pivot 避免最坏情况；三路快排处理大量重复元素
  • 空间：O(log n) 递归栈深度（随机化后期望如此）
  • 最坏情况：每次选到最小/最大元素，退化为 O(n^2)

归并排序（Merge Sort）

// 自顶向下（递归）
void mergeSort(int[] arr, int lo, int hi) {
    if (lo >= hi) return;
    int mid = lo + (hi - lo) / 2;
    mergeSort(arr, lo, mid);
    mergeSort(arr, mid + 1, hi);
    merge(arr, lo, mid, hi);  // 合并两个有序子数组
}

// 自底向上（迭代）：从步长 1 开始，两两归并，步长翻倍
// 逆序对计数：在 merge 过程中，左半部分 arr[i] > 右半部分 arr[j] 时，
// 逆序对数量 += (mid - i + 1)
  • 稳定性：稳定排序（合并时相等元素保持原序）
  • 逆序对：归并排序的副产品，merge 时统计
  • 外部排序：数据无法全部装入内存时，归并排序是首选

堆排序（Heap Sort）

// 大顶堆：parent >= children，用于升序排序
// 小顶堆：parent <= children，用于降序排序 / 优先队列

void heapify(int[] arr, int n, int i) {
    int largest = i, left = 2*i+1, right = 2*i+2;
    if (left < n && arr[left] > arr[largest]) largest = left;
    if (right < n && arr[right] > arr[largest]) largest = right;
    if (largest != i) {
        swap(arr, i, largest);
        heapify(arr, n, largest);
    }
}

// 建堆：从最后一个非叶子节点开始 heapify，O(n)
// 排序：每次取堆顶放末尾，heapify 调整，O(n log n)
  • 优先队列：Java PriorityQueue 底层是小顶堆
  • TopK 问题：维护大小为 K 的小顶堆，遍历数据，比堆顶大则替换并调整

1.3 二叉树

二叉树遍历

递归遍历

// 前序（根→左→右）
void preorder(TreeNode root) {
    if (root == null) return;
    visit(root);
    preorder(root.left);
    preorder(root.right);
}

// 中序（左→根→右）— BST 有序
// 后序（左→右→根）— 释放资源

迭代遍历（栈）

// 前序迭代
void preorder(TreeNode root) {
    Stack<TreeNode> stack = new Stack<>();
    if (root != null) stack.push(root);
    while (!stack.isEmpty()) {
        TreeNode node = stack.pop();
        visit(node);
        if (node.right != null) stack.push(node.right);
        if (node.left != null) stack.push(node.left);
    }
}

// 中序迭代：一路向左入栈，弹出时访问并转向右子树

层序遍历（BFS）

void levelOrder(TreeNode root) {
    Queue<TreeNode> queue = new LinkedList<>();
    if (root != null) queue.offer(root);
    while (!queue.isEmpty()) {
        int size = queue.size(); // 当前层节点数
        for (int i = 0; i < size; i++) {
            TreeNode node = queue.poll();
            visit(node);
            if (node.left != null) queue.offer(node.left);
            if (node.right != null) queue.offer(node.right);
        }
    }
}

Morris 遍历 O(1) 空间

利用叶子节点的空指针指向中序前驱/后继，实现 O(1) 空间遍历。遍历完成后恢复树结构。

  • 前序/中序 Morris：O(n) 时间 O(1) 空间
  • 后序 Morris：需要翻转路径，实现较复杂

二叉搜索树（BST）

  • 性质：左子树所有节点 < 根 < 右子树所有节点
  • 中序遍历：BST 的中序遍历结果是升序序列
  • 操作复杂度：查找/插入/删除平均 O(log n)，最坏退化为链表 O(n)
  • 验证 BST：递归传递上下界，或中序遍历检查是否严格递增

特性AVL 树红黑树B+ 树

B 树 vs B+ 树

B 树

  • 所有节点都存储数据
  • 关键字不重复出现在不同层
  • 没有叶子节点链表
  • 适合随机读取

B+ 树

  • 只有叶子节点存储数据
  • 非叶子节点是索引冗余
  • 叶子节点用双向链表连接
  • 支持范围查询和顺序访问
  • 扇出更高，树更矮
为什么数据库用 B+ 树？① 非叶子节点不存数据，扇出高，树矮，IO 次数少；② 叶子链表支持高效范围查询；③ 所有查询路径长度相同，性能稳定。

1.5 图算法

BFS 与 DFS

BFS（广度优先）

  • 使用队列，逐层扩展
  • 适合求最短路径（无权图）
  • 空间复杂度 O(V)（队列）
  • 应用：最短路径、层序遍历、拓扑排序（Kahn）

DFS（深度优先）

  • 使用栈（或递归），深入探索
  • 适合求连通性、回溯
  • 空间复杂度 O(V)（递归栈）
  • 应用：连通分量、环检测、拓扑排序、回溯

最短路径算法

算法适用场景时间复杂度限制
Dijkstra单源最短路径、非负权边O((V+E) log V)（优先队列）不能处理负权边
Bellman-Ford单源最短路径、可有负权边O(VE)不能处理负权环
Floyd-Warshall所有顶点对最短路径O(V^3)不能处理负权环
SPFA单源最短路径、稀疏图平均 O(E)，最坏 O(VE)被卡时退化严重

最小生成树

Prim 算法

  • 从一个顶点出发，每次选最小权边扩展
  • 类似 Dijkstra，使用优先队列
  • 适合稠密图
  • 时间：O(E log V)

Kruskal 算法

  • 按边权排序，依次加入不构成环的边
  • 使用并查集判断环
  • 适合稀疏图
  • 时间：O(E log E)

拓扑排序

  • 前提：有向无环图（DAG）
  • Kahn 算法（BFS）：入度为 0 的入队，每次取出减少邻居入度
  • DFS 算法：后序遍历的逆序即拓扑序
  • 应用：课程安排、任务调度、编译依赖
  • 环检测：若拓扑排序结果节点数 < 总节点数，说明有环

1.6 链表

链表经典操作

反转链表

// 迭代法
ListNode reverse(ListNode head) {
    ListNode prev = null, curr = head;
    while (curr != null) {
        ListNode next = curr.next;
        curr.next = prev;
        prev = curr;
        curr = next;
    }
    return prev;
}

// 递归法：reverse(node.next) 后
// node.next.next = node; node.next = null;

环检测（Floyd）

boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {
            // 找环入口：从 head 和相遇点同步走
            ListNode entry = head;
            while (entry != slow) {
                entry = entry.next;
                slow = slow.next;
            }
            return true; // entry 即环入口
        }
    }
    return false;
}

LRU 缓存

// 哈希表 + 双向链表，O(1) get/put
class LRUCache {
    int capacity;
    Map<Integer, Node> map = new HashMap<>();
    Node head = new Node(), tail = new Node(); // 哨兵节点

    // get(key)：存在则移到链表头部，返回值
    // put(key, val)：存在则更新并移到头部；不存在则新增到头部

1.7 哈希表与字符串

哈希表为什么快？冲突怎么解决？

面试不要只回答“平均 O(1)”。哈希表先对 key 计算 hash，再通过 index = (n - 1) & hash（容量为 2 的幂时）定位桶；真正的性能取决于负载因子、hash 扰动、冲突分布和扩容成本。

考点面试回答要点工程影响
链地址法桶内挂链表；Java 8 冲突链表过长时树化为红黑树平均 O(1)，极端冲突最坏 O(n) / O(log n)
开放寻址冲突后按探测序列找下一个空槽，删除通常需要墓碑标记缓存友好，但扩容和删除更复杂
扩容元素数超过 capacity × loadFactor 时扩容并重新分桶单次可能 O(n)，高并发初始化应预估容量
一致性哈希节点和 key 映射到哈希环，用虚拟节点改善倾斜缓存集群扩缩容时减少迁移数据
高频追问：为什么 HashMap 的容量通常是 2 的幂？可以用位运算代替取模，且扩容时元素只需留在原位置或移动 oldCap，分布和迁移都更高效。key 若可变，放入 Map 后改变参与 hashCode 的字段，会导致“找不到自己”。

字符串匹配：别只会暴力

算法核心思路复杂度/常考点
暴力匹配主串逐位尝试，失配后回退最坏 O(nm)，代码简单但重复比较多
KMP用 next / lps 表记录模式串最长相等前后缀，主串指针不回退预处理 O(m)，匹配 O(n+m)；next 的定义要说清楚
Trie公共前缀共享路径，节点表示前缀而非完整字符串插入/查询 O(L)，适合词频、前缀搜索、敏感词过滤
字符串哈希前缀哈希 O(1) 判断子串相等存在碰撞，工程上可双哈希或与实际比较结合

1.8 栈、队列与堆：场景决定结构

高频数据结构选择题

结构核心操作典型题型回答时的关键细节
单调栈维护单调递增/递减序列下一个更大元素、柱状图最大矩形每个元素最多入栈出栈一次，总复杂度 O(n)

1.9 并查集与前缀树

并查集（Union-Find）

初始化 parent[i] = i
→
find：路径压缩
→
union：按秩/大小合并
→
判断连通性 / 判环
  • 用途：动态连通分量、Kruskal 最小生成树、岛屿合并、无向图判环。
  • 为什么近似 O(1)：路径压缩 + 按秩合并后，均摊复杂度为 O(α(n))，α(n) 增长极慢。
  • 易错点：并查集适合“合并后查询”，不擅长删除边；有向图判环不能直接照搬无向图并查集。

2.1 动态规划

动态规划核心思想

最优子结构
→
重叠子问题
→
状态转移方程
→
自底向上/记忆化
  • 最优子结构：问题的最优解包含子问题的最优解
  • 重叠子问题：递归过程中同一子问题被多次计算
  • 状态转移方程：dp[i] 与 dp[i-1] 等的关系
  • 两种实现：自顶向下（递归 + 记忆化）vs 自底向上（迭代 + DP 表）

经典 DP 问题

问题状态定义转移方程复杂度
0-1 背包dp[i][w] = 前 i 件物品容量 w 的最大价值dp[i][w] = max(dp[i-1][w], dp[i-1][w-wi]+vi)O(nW)
完全背包同上，物品可重复选dp[i][w] = max(dp[i-1][w], dp[i][w-wi]+vi)O(nW)
LCSdp[i][j] = s1[0..i] 与 s2[0..j] 的最长公共子序列s1[i]==s2[j] ? dp[i-1][j-1]+1 : max(dp[i-1][j],dp[i][j-1])O(mn)
LISdp[i] = 以 arr[i] 结尾的最长递增子序列dp[i] = max(dp[j]+1) for j < i and arr[j] < arr[i]O(n^2) / O(n log n)
编辑距离dp[i][j] = s1[0..i] 转为 s2[0..j] 的最少操作s1[i]==s2[j] ? dp[i-1][j-1] : 1+min(增,删,改)O(mn)
区间 DPdp[i][j] = 区间 [i,j] 的最优解dp[i][j] = min/max(dp[i][k]+dp[k+1][j]+cost)O(n^3)
状态压缩 DPdp[mask] = 集合 mask 的最优解枚举 mask 的子集转移O(2^n * n)
LIS 的 O(n log n) 优化：维护一个 tails 数组，tails[i] 表示长度为 i+1 的递增子序列的最小末尾元素，用二分查找更新。

2.2 贪心算法

贪心核心思想

  • 贪心选择性质：局部最优选择能导致全局最优
  • 最优子结构：问题的最优解包含子问题的最优解
  • 与 DP 的区别：贪心每步只考虑当前最优，不回头；DP 考虑所有子问题

经典贪心问题

问题贪心策略说明
活动选择按结束时间排序，选不冲突的最早结束活动结束越早，留给后续活动的时间越多
区间调度按结束时间排序，贪心选择可证明最优
哈夫曼编码每次选频率最小的两个节点合并构建最优前缀编码树
Kruskal MST按边权排序，选不形成环的最小边并查集判环
跳跃游戏维护当前能到达的最远位置最远位置 ≥ 终点即可
分糖果优先满足需求小的排序后贪心分配

2.3 回溯法

回溯模板

void backtrack(路径, 选择列表) {
    if (满足结束条件) {
        result.add(路径);
        return;
    }
    for (选择 : 选择列表) {
        做选择;           // 路径.add(选择)
        backtrack(路径, 选择列表);
        撤销选择;         // 路径.remove(选择)
    }
}
  • 本质：穷举所有可能，通过剪枝减少搜索空间
  • 时间复杂度：通常为指数级，剪枝可大幅降低

问题关键思路优化
N 皇后逐行放置，检查列/对角线冲突用三个集合记录列、主对角线、副对角线
全排列每次选一个未使用的数used[] 数组标记
子集每个元素选或不选start 参数避免重复
组合总和排序后递归，可重复选跳过重复元素、target < 0 剪枝
数独逐格尝试 1-9位运算记录行/列/宫的已用数字

2.4 双指针 / 滑动窗口 / 二分查找

双指针

对撞指针

  • 左右指针从两端向中间逼近
  • 适用：有序数组、回文判断
  • 经典题：两数之和（有序）、接雨水、盛最多水

快慢指针

  • 慢指针每次走 1 步，快指针每次走 2 步
  • 适用：链表环检测、找中间节点
  • 经典题：环形链表、删除倒数第 N 个节点

滑动窗口

// 滑动窗口模板
int slidingWindow(string s) {
    int left = 0, right = 0, result = 0;
    Map<Character, Integer> window = new HashMap<>();
    while (right < s.length()) {
        char c = s.charAt(right);
        right++;
        // 更新窗口内数据
        while (窗口需要收缩) {
            char d = s.charAt(left);
            left++;
            // 更新窗口内数据
        }
        result = Math.max(result, right - left);
    }
    return result;
}
  • 核心：右指针扩展窗口，左指针收缩窗口，维护窗口内状态
  • 适用：最长/最短子串、包含所有字符的子串
  • 复杂度：O(n)，每个元素最多进出窗口各一次

二分查找

// 标准二分（左闭右闭）
int binarySearch(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;  // 防溢出
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

// 变种：查找左边界 / 右边界 / 第一个 ≥= target
  • 适用：有序数组、旋转有序数组、二分答案
  • 防溢出：mid = lo + (hi - lo) / 2
  • 二分答案：将最优化问题转化为判定问题

🎤第三部分：模拟面试

HashMap 为什么容量是 2 的幂？链表什么时候树化？
参考：容量为 2 的幂时，(n - 1) & hash 等价于取模，计算快且扩容时只需判断新增的高位是否为 1 来决定留在原桶还是移动 oldCap。Java 8 中一个桶的链表长度达到 8 且容量至少 64 时才树化，容量太小时优先扩容，避免小表因偶发冲突付出红黑树维护成本。
追问：为什么重写 equals 必须重写 hashCode？相等对象必须落到同一桶，否则 Map 会先按 hash 定位失败，违反契约。
如何在 O(n) 时间内求滑动窗口最大值？为什么不是每次排序？
参考：使用单调递减双端队列存下标。新元素入队前，从队尾删除所有不可能成为最大值的更小元素；窗口右移时删除队头过期下标，队头即当前最大值。每个下标最多入队和出队一次，因此总复杂度 O(n)，空间 O(k)。每次排序是 O(nk log k)，堆则是 O(n log k)。
如何判断一道题用 DP、贪心还是回溯？
参考：先看是否存在“选择后不影响未来”的贪心选择性质；无法证明时优先考虑 DP。若目标是枚举所有方案、排列组合或需要撤销选择，使用回溯，并通过排序去重、剪枝、记忆化降低复杂度。DP 要明确状态、选择、转移、初始化和遍历顺序，不能只套模板。
快速排序的时间复杂度分析？什么情况下退化为 O(n^2)？如何优化？
参考：快排平均 O(n log n)，每次 partition 将数组分为大致相等的两部分，递归深度 O(log n)，每层 O(n)。最坏情况是每次选到最小或最大元素（如已排序数组选首元素），退化为 O(n^2)。
优化：① 随机化选 pivot；② 三数取中（median-of-three）；③ 三路快排处理大量重复元素；④ 小规模切换插入排序。
如何判断一个二叉树是否是平衡二叉树？
参考：自底向上递归，对每个节点求左右子树高度，若高度差 > 1 返回 -1 表示不平衡，否则返回 max(left, right) + 1。时间 O(n)，避免了自顶向下重复计算。
追问：自顶向下的方法每个节点会重复计算高度，时间 O(n log n) ~ O(n^2)，不如自底向上高效。
Dijkstra 算法的原理？为什么不能处理负权边？
参考：Dijkstra 是贪心算法，每次从优先队列中取出距离最小的未访问节点，更新其邻居的距离。它假设一旦节点被确定最短距离，就不会再被更新。负权边打破了这个假设：已确定的节点可能通过负权边被更短路径更新。
解决方案：负权边用 Bellman-Ford 或 SPFA 算法。
动态规划和贪心算法有什么区别？如何判断用哪个？
参考：贪心每步选局部最优，不回头，效率高但不一定能得到全局最优。DP 考虑所有子问题，保证全局最优但可能更慢。
判断方法：① 尝试用贪心，看能否举出反例；② 如果问题具有贪心选择性质（局部最优导致全局最优），用贪心；③ 如果有重叠子问题和最优子结构但不满足贪心选择性质，用 DP。
例子：0-1 背包不能贪心（反例：价值/重量比最大的物品未必选），用 DP；分数背包可以贪心（按单位价值排序）。
LRU 缓存的实现原理？如何做到 O(1) 的 get 和 put？
参考：使用哈希表 + 双向链表。哈希表存 key 到链表节点的映射，保证 O(1) 查找。双向链表维护访问顺序，最近访问的放头部，最久未使用的在尾部。get 时将节点移到头部；put 时新增到头部，超出容量则删除尾部节点。所有操作都是 O(1)。
追问：为什么用双向链表而不是单向链表？因为删除节点需要 O(1) 访问前驱，双向链表可以直接通过 node.prev 获取。
如何在 O(n log n) 时间内求最长递增子序列（LIS）？
参考：维护一个 tails 数组，tails[i] 表示长度为 i+1 的递增子序列的最小末尾元素。遍历数组，对每个元素用二分查找在 tails 中找到第一个 ≥ 它的位置：若在末尾则追加（序列变长），否则替换（保持末尾最小）。tails 数组始终有序，最终长度即 LIS 长度。
注意：tails 数组不是 LIS 本身，要还原 LIS 需要额外记录前驱。
图的拓扑排序有哪些方法？如何检测有向图中是否有环？
参考：① Kahn 算法（BFS）：维护入度数组，将入度为 0 的节点入队，每次取出减少邻居入度。若结果节点数 < 总数，说明有环。② DFS：后序遍历的逆序即拓扑序。用三色标记（白/灰/黑），遇到灰色节点说明有环。
追问：实际工程中常用 Kahn 算法，因为直观且能同时检测环。
如何用两个栈实现一个队列？用两个队列实现一个栈？
参考：两栈实现队列：push 栈负责入队，pop 栈负责出队。出队时若 pop 栈为空，将 push 栈全部倒入 pop 栈。均摊 O(1)。
两队列实现栈：每次 push 到非空队列（保证一个队列始终为空），pop 时将非空队列的前 n-1 个元素移到另一个队列，最后一个即栈顶。
B 树和 B+ 树有什么区别？为什么 MySQL InnoDB 使用 B+ 树？
参考：① B+ 树只有叶子节点存数据，非叶子节点只存索引，扇出更高，树更矮，IO 更少；② B+ 树叶子节点用双向链表连接，支持高效范围查询和顺序遍历；③ B+ 树所有查询都走到叶子节点，性能稳定（B 树可能在任意层命中，性能不一致）。
追问：MongoDB 用 B 树是因为它更多是单条文档查询，不需要范围查询优化。
