Node.js vs 浏览器事件循环

浏览器事件循环

  • 一个宏任务 → 清空微任务 → 渲染 → 下一个宏任务
  • 微任务：Promise.then、MutationObserver
  • 宏任务：setTimeout、setInterval、I/O
  • 渲染在微任务之后、宏任务之前

Node.js 事件循环

  • 6 个阶段依次执行（timers → poll → check 等）
  • 每个阶段执行完后清空微任务
  • process.nextTick 优先级高于 Promise.then
  • setImmediate 在 check 阶段执行
// Node.js 事件循环 6 个阶段：
// 1. timers：执行 setTimeout / setInterval 回调
// 2. pending callbacks：执行系统级回调（如 TCP 错误）
// 3. idle, prepare：内部使用
// 4. poll：执行 I/O 回调，计算等待时间
// 5. check：执行 setImmediate 回调
// 6. close callbacks：执行 close 事件回调

// Node.js 中的特殊行为
setImmediate(() => console.log('immediate'));
setTimeout(() => console.log('timeout'), 0);
// 输出顺序不确定（取决于事件循环进入 timers 阶段的时机）

// process.nextTick vs Promise.then
process.nextTick(() => console.log('nextTick'));
Promise.resolve().then(() => console.log('promise'));
// 输出：nextTick → promise
// nextTick 在当前阶段结束后立即执行，优先级最高

闭包与作用域

闭包原理

// 闭包（Closure）：函数能够访问其定义时所在的词法作用域
// 即使该函数在其他地方执行

function createCounter() {
  let count = 0;  // 局部变量，外部无法直接访问
  return {
    increment() { return ++count; },
    decrement() { return --count; },
    getCount() { return count; }
  };
}

const counter = createCounter();
counter.increment(); // 1
counter.increment(); // 2
counter.getCount();  // 2
// count 变量通过闭包存活，不会被 GC 回收

// 闭包的底层机制：词法作用域 + 作用域链
// JS 引擎通过 [[Environment]] 内部属性记录函数定义时的作用域链
// 调用函数时，创建新的执行上下文，其作用域链 = [[Environment]] + 当前变量对象

闭包应用：防抖 / 节流 / 柯里化

// 防抖（Debounce）：延迟执行，多次触发重新计时
function debounce(fn, delay) {
  let timer = null;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}
// 应用：搜索框输入、窗口 resize

// 节流（Throttle）：固定间隔执行一次
function throttle(fn, interval) {
  let lastTime = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}
// 应用：滚动事件、鼠标移动、按钮防重复点击

// 柯里化（Currying）：将多参数函数转为一系列单参数函数
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return function(...args2) {
      return curried.apply(this, args.concat(args2));
    };
  };
}

const add = curry((a, b, c) => a + b + c);
add(1)(2)(3);     // 6
add(1, 2)(3);     // 6
add(1)(2, 3);     // 6

闭包与内存泄漏

// 闭包持有外部变量的引用，导致变量无法被 GC 回收

// 内存泄漏示例
function leak() {
  const largeData = new Array(1000000).fill('*');
  return function() {
    // 即使不使用 largeData，闭包也会持有整个作用域的引用
    // 现代 JS 引擎会优化未使用的变量（V8 的 Dead Code Elimination）
    console.log('leak');
  };
}

// 安全做法：不需要的引用手动置 null
function safe() {
  let largeData = new Array(1000000).fill('*');
  const result = process(largeData);
  largeData = null; // 手动释放引用
  return function() {
    console.log(result);
  };
}

// 2. 事件监听器未及时移除
// 3. 缓存无限增长

new 关键字的过程

// new 操作符的执行过程：
// 1. 创建一个空对象 {}
// 2. 将对象的 __proto__ 指向构造函数的 prototype
// 3. 将构造函数的 this 指向该对象并执行
// 4. 如果构造函数返回对象则使用该对象，否则返回新创建的对象

// 手写 new
function myNew(Constructor, ...args) {
  // 1. 创建空对象，链接原型
  const obj = Object.create(Constructor.prototype);
  // 2. 执行构造函数
  const result = Constructor.apply(obj, args);
  // 3. 判断返回值
  return result instanceof Object ? result : obj;
}

继承方式对比

方式原理优点缺点
原型链继承Sub.prototype = new Super()简单引用类型共享、无法传参
构造函数继承Super.call(this)可传参、不共享方法不能复用（每次创建新函数）
组合继承原型链 + 构造函数可传参、方法复用调用两次父构造函数
寄生组合继承Object.create + call最优方案实现稍复杂
ES6 classextends + super语法清晰本质是寄生组合继承的语法糖
 
// 寄生组合继承（最优方案）
function inheritPrototype(Sub, Super) {
  const proto = Object.create(Super.prototype); // 创建父类原型副本
  proto.constructor = Sub;                       // 修复 constructor
  Sub.prototype = proto;                         // 设置子类原型
}

function Parent(name) {
  this.name = name;
}
Parent.prototype.sayHello = function() {
  console.log(`Hello, I'm ${this.name}`);
};

function Child(name, age) {
  Parent.call(this, name); // 继承属性（只调用一次父构造函数）
  this.age = age;
}
inheritPrototype(Child, Parent); // 继承方法

// ES6 class 等价实现
class Child extends Parent {
  constructor(name, age) {
    super(name);
    this.age = age;
  }
}

// Promise 基本用法
const promise = new Promise((resolve, reject) => {
  if (success) {
    resolve(value);   // 状态变为 fulfilled
  } else {
    reject(reason);   // 状态变为 rejected
  }
});

promise
  .then(value => { /* fulfilled */ })
  .catch(reason => { /* rejected */ })
  .finally(() => { /* 无论成功失败 */ });

// 链式调用
fetch('/api/user')
  .then(res => res.json())           // 返回新 Promise
  .then(user => fetch(`/api/orders/${user.id}`))
  .then(res => res.json())
  .then(orders => console.log(orders))
  .catch(err => console.error(err));  // 捕获链中任何错误

// Promise 静态方法
Promise.all([p1, p2, p3])    // 全部成功才 resolve，一个失败就 reject
Promise.allSettled([p1, p2]) // 等待所有完成（不管成功失败）
Promise.race([p1, p2])       // 第一个完成的结果（无论成功失败）
Promise.any([p1, p2])        // 第一个成功的结果（全部失败才 reject）

手写简化版 Promise

class MyPromise {
  constructor(executor) {
    this.state = 'pending';
    this.value = undefined;
    this.callbacks = [];

    const resolve = (value) => {
      if (this.state !== 'pending') return;
      this.state = 'fulfilled';
      this.value = value;
      this.callbacks.forEach(cb => cb.onFulfilled(value));
    };

    const reject = (reason) => {
      if (this.state !== 'pending') return;
      this.state = 'rejected';
      this.value = reason;
      this.callbacks.forEach(cb => cb.onRejected(reason));
    };

    try {
      executor(resolve, reject);
    } catch (err) {
      reject(err);
    }
  }

  then(onFulfilled, onRejected) {
    return new MyPromise((resolve, reject) => {
      const handle = (fn) => {
        try {
          const result = fn(this.value);
          if (result instanceof MyPromise) {
            result.then(resolve, reject);
          } else {
            resolve(result);
          }
        } catch (err) {
          reject(err);
        }
      };

      if (this.state === 'fulfilled') {
        setTimeout(() => handle(onFulfilled), 0);
      } else if (this.state === 'rejected') {
        setTimeout(() => handle(onRejected), 0);
      } else {
        this.callbacks.push({
          onFulfilled: () => handle(onFulfilled),
          onRejected: () => handle(onRejected)
        });
      }
    });
  }

  catch(onRejected) {
    return this.then(null, onRejected);
  }
}

// async 函数总是返回 Promise
async function fetchData() {
  const user = await fetchUser();    // 等待 Promise resolve

this 绑定规则（优先级从高到低）

规则场景this 指向
new 绑定new Foo()新创建的对象
显式绑定call / apply / bind指定的对象

// 1. 默认绑定
function foo() {
  console.log(this); // 非严格模式: window, 严格模式: undefined
}
foo();

// 2. 隐式绑定
const obj = {
  name: 'test',
  foo() { console.log(this.name); } // 'test'（this = obj）
};
obj.foo();

// 隐式丢失
const fn = obj.foo;
fn(); // undefined（赋值后独立调用，this 变为 window）

// 3. 显式绑定
function greet(greeting) {
  console.log(greeting + ', ' + this.name);
}
greet.call({ name: 'Alice' }, 'Hello');   // 立即调用
greet.apply({ name: 'Alice' }, ['Hello']); // 立即调用（参数为数组）
const bound = greet.bind({ name: 'Alice' }); // 返回新函数，永久绑定
bound('Hello');

// 4. new 绑定
function Person(name) {
  this.name = name; // this = 新创建的对象
}
new Person('Alice');

// 箭头函数：没有自己的 this，继承外层作用域的 this
const obj2 = {
  name: 'test',
  foo: () => {
    console.log(this.name); // undefined（this 是外层作用域的 this，即 window）
  },
  bar() {
    setTimeout(() => {
      console.log(this.name); // 'test'（箭头函数继承 bar 的 this）
    }, 100);
  }
};
箭头函数的 this 在定义时确定，不可通过 call/apply/bind 修改。箭头函数也不能作为构造函数（不能 new）。

// Promise 并发控制（限制并发数）
async function parallelLimit(tasks, limit = 3) {
  const results = [];
  const executing = new Set();

  for (const [index, task] of tasks.entries()) {
    const p = task().then(result => {
      executing.delete(p);
      return result;
    });
    executing.add(p);
    results[index] = p;

    if (executing.size >= limit) {
      await Promise.race(executing);
    }
  }

  return Promise.all(results);
}

// Promise 重试
async function retry(fn, maxRetries = 3, delay = 1000) {
  for (let i = 0; i <= maxRetries; i++) {
    try {
      return await fn();
    } catch (err) {
      if (i === maxRetries) throw err;
      await new Promise(r => setTimeout(r, delay * 2 ** i));
    }
  }
}

CommonJS vs ESM

CommonJS（CJS）

Node.js 默认

  • require() 同步加载
  • module.exports 导出
  • 运行时加载（值的拷贝）
  • 可在条件语句中使用
  • this 指向 module.exports

ES Module（ESM）

浏览器原生 / Node.js 12+

  • import 静态分析
  • export / export default 导出
  • 编译时加载（值的引用）
  • 必须在顶层使用（静态结构）
  • this 指向 undefined
// CommonJS
const fs = require('fs');              // 内置模块
const lodash = require('lodash');       // 第三方模块
const utils = require('./utils');       // 本地模块

module.exports = { foo: 'bar' };
// 或 exports.foo = 'bar';

// ES Module
import fs from 'fs';                    // 默认导入
import { readFile, writeFile } from 'fs'; // 命名导入
import * as utils from './utils.js';    // 全部导入

export const foo = 'bar';              // 命名导出
export default class MyClass {}         // 默认导出

// 动态导入（按需加载）
const module = await import('./module.js');

// CJS 与 ESM 互操作
// CJS 中使用 ESM：dynamic import()
const { default: lodash } = await import('lodash');

// ESM 中使用 CJS：自动包装为 default 导出
import pkg from 'cjs-package';
const { method } = pkg;

// 1. 使用 as const 断言获取精确类型
const COLORS = ['red', 'green', 'blue'] as const;
type Color = typeof COLORS[number]; // 'red' | 'green' | 'blue'

// 2. 使用 discriminated union 实现类型安全的联合类型
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rectangle'; width: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2; // TS 自动收窄类型
    case 'rectangle':
      return shape.width * shape.height;
  }
}

// 3. 函数重载
function createElement(tag: 'a'): HTMLAnchorElement;
function createElement(tag: 'div'): HTMLDivElement;
function createElement(tag: string): HTMLElement;
function createElement(tag: string): HTMLElement {
  return document.createElement(tag);
}

// 4. 类型守卫
function isString(value: unknown): value is string {
  return typeof value === 'string';
}

function process(value: string | number) {
  if (isString(value)) {
    console.log(value.toUpperCase()); // TS 知道这里 value 是 string
  }
}

  return obj[key];

第三部分：模拟面试

请解释 JavaScript 的事件循环机制，宏任务和微任务的执行顺序是什么？
参考：JS 是单线程的，通过事件循环实现异步。事件循环不断执行以下步骤：1）从调用栈中执行同步代码；2）调用栈清空后，清空微任务队列（所有微任务）；3）从宏任务队列取一个宏任务执行；4）重复步骤 2 和 3。
微任务优先级高于宏任务。每次执行完一个宏任务后，会清空所有微任务，然后才执行下一个宏任务。微任务包括 Promise.then/catch/finally、MutationObserver、queueMicrotask。宏任务包括 setTimeout、setInterval、I/O、UI 渲染。
追问：Node.js 的事件循环有什么不同？ Node.js 事件循环分为 6 个阶段（timers → pending → idle → poll → check → close），每个阶段执行完后清空微任务。process.nextTick 的优先级高于 Promise.then。
什么是闭包？闭包有哪些应用场景和注意事项？
参考：闭包是指函数能够访问其定义时所在的词法作用域，即使该函数在其他地方执行。本质是函数的 [[Environment]] 内部属性记录了创建时的作用域链。
应用场景：1）数据封装和私有变量（模块模式）；2）函数工厂（柯里化、偏函数）；3）回调函数保持上下文（事件处理、定时器）；4）防抖和节流。
注意事项：1）闭包持有外部变量引用，可能导致内存泄漏（不再需要时手动置 null）；2）循环中的闭包陷阱（用 let 替代 var，或使用 IIFE）；3）闭包变量是引用而非拷贝。
追问：循环中的闭包经典问题？ for 循环中 var 声明的变量被所有回调共享（因为 var 是函数作用域）。解决：1）用 let（块作用域）；2）IIFE 创建独立作用域。
JavaScript 的原型链是什么？new 操作符做了什么？
参考：每个对象都有一个 __proto__ 属性指向其构造函数的 prototype。当访问对象的属性时，先在对象自身查找，找不到则沿 __proto__ 向上查找，直到 null，形成原型链。
new 操作符做了 4 件事：1）创建一个空对象 {}；2）将对象的 __proto__ 指向构造函数的 prototype；3）将构造函数的 this 指向该对象并执行；4）如果构造函数返回对象则使用该对象，否则返回新创建的对象。
ES6 的 class 是基于原型链的语法糖，extends + super 实现继承，本质是寄生组合继承。
追问：__proto__ 和 prototype 有什么区别？ __proto__ 是每个对象都有的内部属性（指向原型），prototype 只有函数才有（作为构造函数时，实例的 __proto__ 指向它）。
Promise 的三种状态是什么？手写一个简化版 Promise 需要注意什么？
参考：Promise 有三种状态：pending（初始）、fulfilled（成功）、rejected（失败）。状态只能从 pending 变为 fulfilled 或 rejected，不可逆转。
手写 Promise 需要注意：1）executor 同步执行，但 then/catch 回调要异步执行（微任务，用 setTimeout 或 queueMicrotask 模拟）；2）支持链式调用（then 返回新 Promise）；3）值穿透（then 的参数不是函数时，值透传给下一个 then）；4）错误冒泡（catch 捕获链中任何错误）；5）支持 Promise 解析过程（then 回调返回 Promise 时要等待 resolve）。
追问：Promise.all 和 Promise.allSettled 有什么区别？ all 在任意一个 Promise reject 时立即 reject，其他结果被忽略。allSettled 等待所有 Promise 完成（无论成功失败），返回每个 Promise 的状态和结果。
箭头函数和普通函数有什么区别？this 的绑定规则是什么？
参考：箭头函数和普通函数的核心区别：1）箭头函数没有自己的 this，继承外层作用域的 this（定义时确定，不可改变）；2）箭头函数不能作为构造函数（不能 new）；3）箭头函数没有 arguments 对象（使用 rest 参数代替）；4）箭头函数没有 prototype 属性。
this 的绑定规则（优先级从高到低）：1）new 绑定：new Foo() → this 是新对象；2）显式绑定：call/apply/bind → this 是指定对象；3）隐式绑定：obj.fn() → this 是调用对象；4）默认绑定：fn() → 严格模式 undefined，非严格 window。
追问：setTimeout 中的 this 指向？ 普通函数回调中 this 是 window（默认绑定）。箭头函数回调中 this 继承外层的 this。
TypeScript 的泛型、条件类型、映射类型分别是什么？
参考：泛型是参数化的类型，允许在定义时不指定类型，使用时再确定。如 function identity<T>(arg: T): T。泛型可以约束（extends）、设置默认值（= DefaultType）。
条件类型是三元表达式的类型版本：T extends U ? X : Y。配合 infer 关键字可以在条件分支中推断类型（如提取函数返回类型 T extends (...args: any[]) => infer R ? R : never）。
映射类型遍历联合类型的每个成员生成新类型：{ [K in keyof T]: T[K] }。内置工具类型 Partial、Required、Readonly、Pick、Omit 都是映射类型的实现。
追问：Pick 和 Omit 怎么实现的？ type Pick<T, K extends keyof T> = { [P in K]: T[P] }；type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>。
CommonJS 和 ES Module 有什么区别？Tree Shaking 的原理是什么？
参考：CommonJS 是运行时加载，require() 同步执行，得到的是值的拷贝。ES Module 是编译时静态分析，import/export 在代码解析阶段确定依赖关系，得到的是值的引用。ESM 支持 Tree Shaking，CJS 不支持。
Tree Shaking 的原理：ESM 的 import/export 是静态结构（必须在顶层），打包工具在编译时可以分析出哪些导出没有被使用，从而在最终产物中删除未使用的代码。CJS 的 require 是动态的（可在条件语句中使用），编译时无法确定哪些模块被使用，所以不能 Tree Shaking。
追问：为什么 package.json 要设置 "type": "module"？ 告诉 Node.js 将 .js 文件视为 ES Module 而非 CommonJS。也可以用 .mjs（ESM）和 .cjs（CJS）扩展名区分。
TypeScript 的类型体操中，infer 关键字有什么用？举例说明。
参考：infer 在条件类型中用于声明一个待推断的类型变量，让 TypeScript 自动推断。类似于函数参数中的形参，但用在类型层面。
常见用法：1）提取函数返回类型：type Return<T> = T extends (...args: any[]) => infer R ? R : never；2）提取数组元素类型：type Element<T> = T extends (infer E)[] ? E : never；3）提取 Promise 内部类型（递归）：type Awaited<T> = T extends Promise<infer U> ? Awaited<U> : T；4）提取函数参数类型：type Params<T> = T extends (...args: infer P) => any ? P : never。
追问：infer 的约束？ infer 只能在 extends 子句中使用。多个 infer 时，协变位置推断为联合类型，逆变位置推断为交叉类型。
