1.1 SOLID 原则

五大设计原则

原则缩写含义示例
单一职责SRP一个类只有一个变化的原因UserService 只管用户业务，不负责日志和缓存
开闭原则OCP对扩展开放，对修改关闭新增支付方式不修改现有代码，只需实现接口
里氏替换LSP子类可以替换父类而不影响正确性正方形不应继承长方形（setWidth 会破坏行为）

依赖反转DIP高层不依赖低层，都依赖抽象Service 依赖 Repository 接口，不依赖 MySQL 实现

1.2 单例模式

单例模式实现方式

方式线程安全懒加载防反射/序列化推荐
饿汉式是否否简单场景
懒汉式（synchronized）是是否性能差
DCL（双重检查锁）是是否推荐
静态内部类是是否推荐
枚举是否是最佳
 
// DCL 双重检查锁
public class Singleton {
    private static volatile Singleton instance; // volatile 防止指令重排
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {                 // 第一次检查（无锁）
            synchronized (Singleton.class) {
                if (instance == null) {         // 第二次检查（有锁）
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

// 静态内部类（推荐）
public class Singleton {
    private Singleton() {}
    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }
    public static Singleton getInstance() {
        return Holder.INSTANCE; // 类加载时初始化，线程安全且懒加载
    }
}

// 枚举（最佳，Effective Java 推荐）
public enum Singleton {
    INSTANCE;
    public void doSomething() { }
}
为什么 DCL 需要 volatile？instance = new Singleton() 不是原子操作：① 分配内存 → ② 初始化 → ③ 引用赋值。JVM 可能重排为 ①→③→②，导致其他线程获取到未初始化的对象。volatile 禁止重排序。

1.3 工厂模式

工厂方法 vs 抽象工厂

工厂方法（Factory Method）

  • 定义创建对象的接口，子类决定实例化哪个类
  • 每个产品对应一个工厂
  • 符合开闭原则（新增产品只需新增工厂）
  • 示例：LoggerFactory → FileLogger / ConsoleLogger

抽象工厂（Abstract Factory）

  • 创建一系列相关产品的接口
  • 一个工厂生产多个产品
  • 适合产品族场景
  • 示例：GUIFactory → WinFactory（WinButton + WinTextBox）/ MacFactory
// 简单工厂（不属于 GoF，但面试常考）
public class LoggerFactory {
    public static Logger create(String type) {
        switch (type) {
            case "file": return new FileLogger();
            case "console": return new ConsoleLogger();
            default: throw new IllegalArgumentException();
        }
    }
}

1.4 建造者与原型

建造者模式（Builder）

// 链式调用构建复杂对象
public class HttpRequest {
    private String url;
    private String method;
    private Map<String, String> headers;
    private String body;

    public static class Builder {
        private String url;
        private String method = "GET";
        private Map<String, String> headers = new HashMap<>();
        private String body;

        public Builder url(String url) { this.url = url; return this; }
        public Builder method(String method) { this.method = method; return this; }
        public Builder header(String k, String v) { headers.put(k, v); return this; }
        public Builder body(String body) { this.body = body; return this; }
        public HttpRequest build() { return new HttpRequest(this); }
    }
}

// 使用：new HttpRequest.Builder().url("...").method("POST").build();
  • 适用：对象有多个可选参数，构造函数参数过多
  • 变种：Lombok @Builder 自动生成

原型模式（Prototype）

  • 核心：通过克隆（clone）现有对象来创建新对象
  • 深拷贝 vs 浅拷贝：浅拷贝只复制引用，深拷贝递归复制所有引用对象
  • 实现：Java Cloneable 接口（浅拷贝）、序列化/反序列化（深拷贝）、手动递归复制
  • 适用：创建对象成本高（如数据库查询），需要大量相似对象

1.5 代理模式

静态代理 vs 动态代理

静态代理

  • 代理类在编译期就已确定
  • 代理类实现与目标类相同的接口
  • 每个接口需要写一个代理类
  • 简单但不灵活

JDK 动态代理

  • 基于接口，运行时生成代理类
  • Proxy.newProxyInstance(classLoader, interfaces, handler)
  • InvocationHandler 处理方法调用
  • Spring AOP 默认方式

CGLIB 动态代理

  • 基于继承，生成目标类的子类
  • 不需要接口
  • 通过 MethodInterceptor 拦截方法
  • 不能代理 final 类和方法

对比

  • JDK：基于接口，反射调用，创建快
  • CGLIB：基于继承，字节码生成，创建慢但运行快
  • Spring：有接口用 JDK，无接口用 CGLIB
  • Spring Boot 2.x+ 默认使用 CGLIB

1.6 结构型模式

适配器 / 装饰器 / 外观 / 桥接

模式意图关键区别示例
适配器 将不兼容的接口转换为期望的接口 改变接口 Arrays.asList()、InputStreamReader
装饰器 动态地给对象添加职责 不改变接口，增强功能 IO 流包装（BufferedReader）、Collections.synchronizedList
外观 为子系统提供统一的高层接口 简化接口 SLF4J（统一日志接口）、JdbcTemplate
桥接 将抽象与实现分离，使它们独立变化 两个维度独立扩展 JDBC Driver（API + 实现分离）

2.1 行为型模式

策略模式（Strategy）

// 定义算法族，使它们可以互相替换
public interface PaymentStrategy {
    void pay(double amount);
}
public class AlipayStrategy implements PaymentStrategy { ... }
public class WechatPayStrategy implements PaymentStrategy { ... }

public class PaymentContext {
    private PaymentStrategy strategy;
    public void setStrategy(PaymentStrategy s) { this.strategy = s; }
    public void executePayment(double amount) { strategy.pay(amount); }
}
  • 适用：多种算法/策略可互换，避免大量 if-else
  • 示例：排序策略、支付方式、促销折扣、路由策略

观察者模式（Observer）

// 一对多依赖：对象状态变化时通知所有依赖者
public interface Observer {
    void update(String event);
}
public class EventBus {
    private Map<String, List<Observer>> listeners = new HashMap<>();
    public void subscribe(String event, Observer o) { ... }
    public void publish(String event) {
        for (Observer o : listeners.get(event)) o.update(event);
    }
}
  • 适用：事件驱动、发布-订阅、GUI 事件处理
  • 示例：Spring Event、MQ 消费者、Android LiveData

模板方法（Template Method）

// 定义算法骨架，子类实现具体步骤
public abstract class AbstractExportService {
    // 模板方法（final 防止子类覆盖）
    public final void export() {
        validate();       // 公共步骤
        doExport();       // 抽象步骤，子类实现
        log();            // 公共步骤
    }
    protected abstract void doExport();
    private void validate() { ... }
    private void log() { ... }
}
public class CsvExportService extends AbstractExportService {
    protected void doExport() { /* CSV 导出逻辑 */ }
}
  • 适用：算法骨架固定，部分步骤可变
  • 示例：JdbcTemplate、AbstractList、HttpServlet.service()

责任链模式（Chain of Responsibility）

  • 核心：将请求沿着处理链传递，每个处理者决定处理或转发
  • 适用：审批流程、过滤器链、中间件
  • 示例：Servlet Filter 链、Spring Security FilterChain、Netty ChannelPipeline

状态模式（State）

  • 核心：对象内部状态改变时改变其行为，看起来像改变了类
  • 适用：状态机、订单状态流转、TCP 连接状态
  • 与策略的区别：策略是客户端主动选择算法；状态是对象自身根据内部状态自动切换行为

2.2 模式对比与辨析

代理 vs 装饰器

维度代理模式装饰器模式
目的控制对象访问（权限、延迟、缓存）增强对象功能
对象创建代理通常自己创建目标对象装饰器接收已有对象
关注点能否访问如何增强
组合通常不嵌套可以多层嵌套（如 IO 流）

策略 vs 状态

维度策略模式状态模式
切换主体客户端主动设置对象内部自动切换
感知客户端知道有哪些策略客户端不知道内部状态
上下文策略之间互不知道状态之间可以互相转换
示例支付方式选择订单状态流转

观察者 vs 发布订阅

维度观察者模式发布订阅模式
耦合Subject 直接通知 Observer（紧密耦合）通过事件中心解耦（松耦合）
通信Subject 维护 Observer 列表Publisher 和 Subscriber 互不知道
中间件无有（EventBus/Broker）
示例Java Observable、Spring EventRabbitMQ、Kafka、Node.js EventEmitter

🎤第三部分：模拟面试

请说说你对 SOLID 原则的理解，举一个实际项目中的例子。
参考：S 是单一职责，如 UserService 只管用户业务逻辑；O 是开闭原则，如新增支付方式只需新增类实现 PaymentStrategy 接口；L 是里氏替换，子类不能改变父类的语义；I 是接口隔离，不应该强迫实现不需要的方法；D 是依赖反转，Service 依赖 Repository 接口而不是 MySQL 实现。
项目示例：导出功能用策略模式，ExportStrategy 接口有 CsvExport、ExcelExport 实现，新增格式只需新增实现类，符合 OCP。
单例模式有几种实现方式？为什么 DCL 需要 volatile？
参考：饿汉式、懒汉式（synchronized）、DCL、静态内部类、枚举。DCL 需要 volatile 是因为 new Singleton() 分为三步：分配内存、初始化、引用赋值。JVM 可能重排为 1→3→2，导致另一个线程在第一次 if 检查时拿到未初始化的对象。volatile 禁止指令重排序。
追问：枚举单例为什么最好？天然线程安全（JVM 保证枚举实例的唯一性）、防止反射攻击（JVM 禁止通过反射创建枚举实例）、防止反序列化破坏（readResolve 由 JVM 保证）。
JDK 动态代理和 CGLIB 动态代理有什么区别？Spring 怎么选择？
参考：JDK 动态代理基于接口，通过 Proxy.newProxyInstance() 在运行时生成代理类，只能代理实现了接口的类。CGLIB 基于继承，通过 ASM 字节码生成目标类的子类，不需要接口，但不能代理 final 类和方法。
Spring 选择：如果目标类有接口，默认用 JDK 动态代理；没有接口用 CGLIB。Spring Boot 2.x 默认使用 CGLIB（proxyTargetClass=true），因为 CGLIB 性能已优化且使用更简单。
策略模式和状态模式有什么区别？
参考：结构类似（都是将行为委托给策略/状态对象），但意图不同。策略模式：客户端主动选择算法，策略之间互不知道，如选择支付方式。状态模式：对象根据内部状态自动切换行为，状态之间可以互相转换，如订单状态流转（待支付→已支付→已发货→已完成）。
关键区别：策略是外部选择，状态是内部驱动。
观察者模式和发布订阅模式有什么区别？
参考：观察者模式：Subject 直接维护 Observer 列表并通知，两者紧密耦合。发布订阅模式：通过事件中心（EventBus/Broker）解耦，Publisher 和 Subscriber 互不知道对方存在。观察者模式是发布订阅的简化版。
追问：Spring Event 是观察者模式（ApplicationEventPublisher 直接发布，EventListener 直接监听），MQ（如 Kafka）是发布订阅模式。
装饰器模式和代理模式有什么区别？
参考：装饰器：动态增强对象功能，不改变接口，可以多层嵌套（如 new BufferedReader(new InputStreamReader(is))）。代理：控制对象访问（权限校验、延迟加载、缓存），代理通常自己创建目标对象。
关键区别：装饰器关注"增强"，代理关注"控制"。装饰器通常由客户端传入被装饰对象，代理通常自己管理目标对象的生命周期。
Spring 中用到了哪些设计模式？请举例说明。
参考：① 工厂：BeanFactory 创建 Bean；② 单例：Bean 默认单例；③ 代理：AOP 用 JDK/CGLIB 动态代理；④ 模板方法：JdbcTemplate 封装 JDBC 操作；⑤ 策略：Resource 接口有 ClassPathResource、FileSystemResource 等实现；⑥ 观察者：ApplicationEvent + @EventListener；⑦ 责任链：FilterChain、Interceptor 链；⑧ 适配器：HandlerAdapter 适配不同类型的 Handler。
