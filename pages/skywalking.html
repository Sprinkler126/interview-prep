Trace/Span 生命周期
  • 使用 Java Agent 的 premain() 方法在类加载前注册转换器
  • 通过 ASM 字节码操作库修改目标类的字节码
  • 在方法入口/出口插入增强代码（创建 Span、记录时间等）
  • 插件机制：不同中间件（Spring、Dubbo、MySQL、Redis）使用不同插件
  • 零侵入：应用代码无需修改，只需启动时添加 Agent 参数

Agent 配置

# 启动参数
java -javaagent:/path/to/skywalking-agent.jar \
     -Dskywalking.agent.service_name=my-service \
     -Dskywalking.collector.backend_service=oap-server:11800 \
     -jar my-app.jar

# agent.config 核心配置
agent.service_name=${SW_AGENT_NAME:my-service}
collector.backend_service=${SW_AGENT_COLLECTOR_BACKEND_SERVICES:127.0.0.1:11800}
agent.sample_n_per_3_secs=${SW_AGENT_SAMPLE:100}  # 采样率
agent.ignore_suffix=${SW_AGENT_IGNORE_SUFFIX:.jpg,.css,.js}

核心概念

Trace / Span / Segment

概念说明
Trace一次完整的请求链路，由多个 Segment 组成，全局唯一 TraceId
Segment一个服务内的链路片段，是 SkyWalking 的基本传输单元
Span链路中的一个操作单元（如一次 HTTP 调用、一次 DB 查询），包含开始时间、耗时、标签
SpanLayerSpan 的层次分类：Unknown / RPCFramework / HTTP / MQ / Cache / Database
TraceId全局唯一标识，跨服务传播，用于关联所有 Segment

Span 类型

  • Entry Span：服务入口 Span（如接收到 HTTP 请求），一个 Segment 有且只有一个
  • Local Span：本地操作 Span（如本地方法调用、定时任务）
  • Exit Span：服务出口 Span（如发起 HTTP 调用、SQL 查询）

拓扑图

拓扑图类型

  • 服务拓扑：展示服务之间的依赖关系和调用方向
  • 端点拓扑：展示具体 API 端点之间的调用关系
  • 实例拓扑：展示服务实例之间的调用关系
  • 拓扑图自动根据链路数据生成，无需手动配置
  • 支持点击节点查看详细指标（响应时间、吞吐量、错误率）

性能指标

三层指标体系

层级指标说明
Service服务级指标服务的平均响应时间、吞吐量（CPM）、成功率、SLA
Endpoint端点级指标具体 API 的响应时间、吞吐量、错误率
Instance实例级指标服务实例（JVM）的 CPU、内存、GC、线程池

第二部分：场景化讲解

告警规则

告警规则配置

# alarm-settings.yml
rules:
  # 服务响应时间告警
  service_resp_time_rule:
    metrics-name: service_resp_time
    op: ">"
    threshold: 1000        # 1000ms
    period: 10             # 统计周期 10 分钟
    count: 3               # 连续 3 次触发
    silence-period: 5      # 静默 5 分钟
    message: "服务 {name} 响应时间超过 1000ms"

  # 服务成功率告警
  service_sla_rule:
    metrics-name: service_sla
    op: "<"
    threshold: 8000        # 80%（万分比）
    period: 10
    count: 2
    message: "服务 {name} 成功率低于 80%"

  # 实例响应时间告警
  instance_resp_time_rule:
    metrics-name: instance_resp_time
    op: ">"
    threshold: 2000
    period: 10
    count: 3
    message: "实例 {name} 响应时间超过 2000ms"

插件开发与日志集成

Java Agent 插件开发

  • SkyWalking 通过插件机制支持不同中间件的自动追踪
  • 内置插件：Spring MVC、Dubbo、gRPC、MySQL、Redis、Kafka、RabbitMQ 等 70+
  • 自定义插件需要实现 ClassEnhancePluginDefine 类
  • 定义拦截点（构造方法、实例方法、静态方法）和增强逻辑

日志集成（Log4j2 / Logback）

<!-- Logback 集成配置 -->
<appender name="GRPC_LOG" class="org.apache.skywalking.apm.toolkit.log.logback.v1.x.log.GRPCLogClientAppender">
</appender>

<root level="INFO">
    <appender-ref ref="GRPC_LOG"/>
</root>

# 日志中自动注入 TraceId
# %d{yyyy-MM-dd HH:mm:ss} [%tid] [%thread] %-5level %logger{36} - %msg
# [tid] 会被替换为 SkyWalking 的 TraceId
  • 集成后日志自动注入 TraceId，可在 SkyWalking UI 中关联日志和链路
  • 支持 Log4j2、Logback、Log4j 1.x
  • 日志通过 gRPC 上报到 OAP Server

第三部分：模拟面试

SkyWalking 的架构是怎样的？各组件有什么作用？
参考：SkyWalking 由四部分组成：Agent（部署在应用侧，通过字节码增强自动采集链路数据和性能指标）、OAP Server（核心分析平台，接收 Agent 数据进行流式分析和告警）、Storage（存储后端，支持 ES/MySQL/BanyanDB）、UI（Web 界面，展示拓扑图和链路详情）。Agent 通过 gRPC 上报数据到 OAP Server，OAP Server 将分析结果存入 Storage，UI 通过 GraphQL 查询 OAP 展示数据。
SkyWalking 的 Java Agent 是如何实现零侵入的？
参考：SkyWalking 使用 Java Agent 的 premain() 方法在应用启动时注册 ClassFileTransformer，通过 ASM 字节码操作库在类加载时修改目标类的字节码。在方法入口/出口插入增强代码，自动创建 Span、记录时间、传播 TraceId。不同中间件使用不同插件（如 Spring MVC 插件、MySQL 插件）。应用代码无需任何修改，只需启动时添加 -javaagent:skywalking-agent.jar 参数。
参考：Trace 是一次完整的请求链路，全局唯一 TraceId，跨多个服务。Segment 是一个服务内的链路片段，是 SkyWalking 的基本传输单元。Span 是链路中的一个操作单元（如一次 HTTP 调用、一次 DB 查询）。关系：一个 Trace 由多个 Segment 组成（每个服务一个），一个 Segment 由多个 Span 组成。Span 类型有 Entry Span（服务入口）、Exit Span（服务出口）、Local Span（本地操作）。
SkyWalking 和 Zipkin、Jaeger 相比有什么优势？
参考：SkyWalking 的核心优势：1）零侵入：Java Agent 字节码增强，无需修改代码，Zipkin/Jaeger 需要埋点 SDK；2）全功能 APM：自动拓扑图、性能指标、告警一体化，Zipkin/Jaeger 主要聚焦链路追踪；3）告警内置：支持响应时间、成功率等多维度告警规则；4）Apache 顶级项目，社区活跃。Zipkin/Jaeger 的优势：更轻量、更成熟的生态集成。
SkyWalking 的存储后端有哪些选择？生产环境推荐哪个？
参考：支持 H2（开发测试）、MySQL（中小规模）、Elasticsearch（大规模生产首选）、BanyanDB（自研时序数据库，未来方向）。生产环境推荐 Elasticsearch：分布式、高性能、支持海量数据。中小规模可以用 MySQL。BanyanDB 是 SkyWalking 自研的时序数据库，目标是替代 ES 成为首选存储，资源占用更低。
SkyWalking 的告警规则如何配置？
参考：在 alarm-settings.yml 中配置告警规则，每个规则定义：metrics-name（指标名，如 service_resp_time）、op（比较操作符）、threshold（阈值）、period（统计周期）、count（触发次数）、silence-period（静默期）。支持的指标包括服务级（响应时间、吞吐量、SLA）、端点级、实例级。告警通知支持 Webhook，可对接钉钉、Slack、邮件等。
如何将日志与 SkyWalking 的链路追踪关联？
参考：通过 SkyWalking 的日志插件（Log4j2/Logback）集成。配置 GRPCLogClientAppender，日志自动注入 TraceId。在日志格式中使用 %tid 占位符，会被替换为当前链路的 TraceId。这样可以在 SkyWalking UI 中通过 TraceId 关联日志和链路追踪。日志通过 gRPC 上报到 OAP Server，存储在 Storage 中。
